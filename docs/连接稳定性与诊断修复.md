# 连接稳定性与诊断修复

本次针对审查中发现的四个问题和两个优化点进行修改。保持现有应用包名、签名和耳机协议值，不增加蓝牙断开或强制重连音频的操作。

## 四项修复

1. **媒体路由回调异常隔离**：路由回调由独立协程执行，原先的服务调用异常可能进入蓝牙进程的未捕获异常处理。现在回调、延迟切换、路由重试及传输超时任务使用同一异常保护，保留协程取消语义，并尝试写入固定的路由失败诊断；诊断记录本身失败也不会再次向外抛出。该处理不主动断开 A2DP。
2. **通话期间取消摘耳续播**：收到真实来电状态后，取消此前摘耳产生的续播标记；准备续播时还会检查电话状态和音频模式，覆盖普通电话和使用通话音频模式的 VoIP 场景。通话结束后不会执行已经取消的播放指令。
3. **原生 Hook 失败提示**：即使三个进程都回报相同版本，蓝牙的 `native_failed` 也会触发明确警告。未知状态不会被擅自判为失败，旧版进程仍优先提示重启；重新检测成功后清除警告。
4. **空 UUID 缓存补查**：首次识别时，`null` 和空 UUID 数组都会触发 SDP 查询；非空且不匹配的 UUID 不新增查询。查询结果仍必须通过设备识别、当前连接状态和原生 Hook 检查，才能建立控制连接。

## 两项优化

1. **减少完整握手**：电量、佩戴和设备信息等核心状态已具备时，自动补请求和页面刷新仍沿初始化状态机补齐首次功能配置，之后只订阅状态，不再重复完整握手。必要的聆听模式等控制状态仍缺失时，手动重试会重建独立控制通道；仅缺辅助设置时继续使用轻量补请求。核心状态仍缺失时保留原来的有界握手恢复。
2. **细分诊断**：分别记录读取结束（EOF）、Socket 已断开、读取异常、数据处理异常、写入异常、写入超时和发送队列满。保留旧版历史代码兼容；主动关闭控制通道的原因绑定到具体 Socket，避免旧超时掩盖新故障。增加 A2DP 状态及其变化事件，区分“状态补请求次数”和“控制通道重连次数”。新字段只保存固定状态和时间，不保存原始异常文本、设备标识或协议包。

## 验证范围

- 将审查阶段的三个失败场景补入回归测试，并覆盖空 UUID、未知 Hook 结果、重检恢复、普通电话/VoIP、EOF/读异常/处理异常和发送故障分类。
- 验证核心状态就绪时的实际出包内容，确认只发送状态订阅；核心数据缺失时仍允许完整恢复。
- 诊断历史和事件继续通过白名单及长度限制，覆盖新增状态的保存与读取。
- 模拟器验证模块提示及原有设置页面，Release 混淆与 Lint 作为构建检查。

模拟服务异常验证的是代码边界，不代表已经在手机上复现了蓝牙服务崩溃。此前用户报告的“音乐和系统蓝牙同时断开”，仍需要断开时的完整系统日志确认真正原因。目标手机安装新包后需要重启，才能让蓝牙和系统界面进程加载新代码。

## 复查补充：路由定时任务与初始化边界

- 回调之外的 500 毫秒扬声器切换、耳机路由重试及传输超时任务均进入异常保护。故障记录不主动关闭控制 Socket，也不清除摘耳暂停的续播标记；路由恢复后仍按原来的佩戴、通话和输出设备条件决定是否续播。
- 核心状态提前到达时，必须补发尚未发送的功能配置。仅收到完整状态不能让恢复循环过早结束；功能配置已发出后不重复发送握手或功能配置。功能配置发送失败仍保留下一次有界恢复机会。
- 手动恢复以必要控制状态是否完整为界，保留聆听模式缺失时重建控制通道的能力，不修改蓝牙音频连接和原有自动续播条件。
- 新增 8 项永久回归测试。393 项单元测试全部通过，其中包含普通摘戴仅暂停/续播一次、来电/VoIP 取消续播、对话结束续播、路由恢复，以及异常后控制通道保留等检查。故障注入使用模拟服务，不能替代目标手机实测。
